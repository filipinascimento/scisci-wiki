# WoS data-request problem-statement gate

## Summary

Fit-for-purpose WoS access requests can be screened through a concise statement linking objective, needed data, reporting plan, outcomes, and deliverables.

## Canonical Form

- Unit of analysis: data request, research objective, extract scope, deliverable, or institutional approval path.
- Typical representation: data-use request brief with source rationale and expected outputs.
- Mechanism, measurement, or validation target: front-door triage for custom bibliometric extracts.
- Empirical signature: extract approval requires an explicit problem statement and data-use rationale before data delivery..

## Uses in Science of Science

- Operationalizes [fit-for-purpose bibliometric extracts](fit_for_purpose_bibliometric_extracts.md).
- Connects [WoS data-use entitlement ladder](wos_data_use_entitlement_ladder.md) to project planning.
- Useful for preventing speculative, underdocumented extraction requests.

## Operationalization

- Require a short access brief covering problem, data need, source rationale, progress reporting, outcomes, and deliverables.
- Flag speculative or underplanned requests before extraction.
- Record the review path through library, account manager, or provider review.

## Evidence and Validations

- Verified full-text evidence from Birkle et al. (2020) describes an access path through subscription managers and asks researchers to provide a concise summary of required data, rationale, reporting, outcomes, and deliverables.

## Caveats

- A request gate is not a substitute for preregistration or independent validation.
- Gatekeeping can slow legitimate exploratory work if applied too rigidly.
