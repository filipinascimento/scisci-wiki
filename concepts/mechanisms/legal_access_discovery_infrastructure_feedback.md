# Legal access-discovery infrastructure feedback

## Summary

Resolver services and browser extensions make legal OA more visible, and that visibility creates more use, institutional adoption, and measurement data.

## Canonical Form

- Unit of analysis: resolver request, reader session, library system, browser extension, or OA copy.
- Typical representation: feedback loop between resolver adoption, legal-copy discovery, reader use, and measured demand.
- Mechanism, measurement, or validation target: infrastructure-mediated discoverability of legal OA copies.
- Empirical signature: resolver usage and library adoption increase measured access to legally available OA copies..

## Uses in Science of Science

- Extends [open access resolver workflows](../methods/open_access_resolver_workflows.md) from detection into adoption feedback.
- Useful when interpreting [Unpaywall reader-demand sample](../datasets/unpaywall_reader_demand_sample.md) traces.
- Connects discovery infrastructure to [reader-experienced OA rate](../measures/reader_experienced_oa_rate.md).

## Operationalization

- Model API, library, and extension adoption against OA click-throughs, resolver requests, and legal-copy availability.
- Separate user populations using resolver tools from all potential readers.
- Version resolver code and source-fusion rules before comparing demand over time.

## Evidence and Validations

- Verified full-text evidence from Piwowar et al. (2018) describes oaDOI powering Unpaywall, handling heavy daily request volume, and being used by libraries to solve discoverability.
- The same infrastructure also produces the reader-demand sample used in the paper.

## Caveats

- Tool users are selected and not equivalent to all readers.
- Resolver success can reflect interface changes as much as true OA growth.
